# 社区证据发布标准

社区证据任务、Issue 快照、任务账本、采纳记录、逐次复核凭据、贡献历史与公开任务必须作为一个发布单元校验。

- 公开任务至多五个；每个任务只请求一个字段并标注 `预计 2 分钟`。
- 公开任务必须是账本中 `open` 或 `contributed` 状态的精确有序子集；`stale`、关闭或终止任务不得保留在公开列表。
- Issue、任务、主体、字段、版本和规范 GitHub Issue URL 必须逐项一致；聚合发现链接不得伪装成官方证据。
- `accepted-evidence` 只代表人工采纳，`canonical-promoted` 标签也不是晋升授权。系统只访问已采纳的精确 URL，并记录实体、来源等级、字段一致性、冲突与日期五项结果；只有当次成功复核与现有规范字段的精确 URL 绑定同时成立时，才可追加 `promoted`。
- `review/accepted-evidence-revalidation.json` 是追加式复核凭据；超时、非文本内容、不安全地址、超限正文、未知字段或不充分证据均显式降级或失败关闭，不保存响应正文、凭据、请求头或原始异常。
- 共同补证者必须由维护者用 `<!-- accepted-contributor:@login -->` 与同一评论中的唯一证据 URL 绑定。
- 贡献历史只允许追加；当前事件列表必须以前一份已提交或 LKG 事件列表为精确前缀。纠错与撤回以新事件记录，不得删除、改写或重排历史。
- 已采纳贡献者指标必须从精确校验后的 `community/contributions.json` 推导（包含被维护者明确绑定的共同补证者），不得从 Issue 作者或标签查询推断。社区指标只发布聚合值：开放任务数、类别覆盖、本周采纳、新贡献者、陈旧率、无效率和晋升转化率；禁止贡献者排名和个人分数。

面向贡献者的完整流程见 [贡献指南](../CONTRIBUTING.md) 与 [Evidence Review 手册](../community/evidence-review.md)。
