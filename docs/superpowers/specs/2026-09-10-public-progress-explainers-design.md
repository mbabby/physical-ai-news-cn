# 物理 AI 进展解读：一期重构规格

## 定位与完成边界

面向没有机器人专业背景、但关心科技进展的读者。认知本身就是目的，不要求投资、职业规划或其他行动。

产品展示名称：**物理 AI 进展解读**；英文：**Physical AI Explained**。仓库名称、地址及既有资料链接不变。

价值主张：**看懂机器人与物理 AI：现在能做什么，最近进步在哪，还有什么没解决。**

一期不是重写平台：增加一份有版本的进展解读产物，接入现有生成与事务发布链路，由同一产物驱动首页和 README。采集、规范事实、双账本、公司档案、研究库、旧页面及 Feed 继续保留。

## 阅读产品

首页主线为“近期值得理解的变化”，最多三篇，允许零篇。不使用“每日必读”“每天三大突破”等承诺，不用候选消息补足数量。

每篇解读包括：

1. 通俗标题与两句事实简介：明确主体及发生的事，首次出现的必要术语就地解释。
2. 这次改变了什么：只有具备同任务、同条件的比较证据才输出前后对比；否则明确写本次新增的信息，不推断过去做不到。
3. 为什么值得理解：明确标为“解读”，解释具体意义，不输出投资推荐、未来成功保证或通用套话。
4. 还不能说明什么：说明已知条件、限制，以及缺少公开证据的部分。缺少公开证据不等于尚未实现。
5. 进一步了解：背景解释、原始证据和日期，按需展开，不强迫用户先理解证据系统。

“演示”“作者报告”“独立复现”“试点”“部署”等是证据情境，不构成线性升级阶梯或行业成熟度分数。官方公告确认发布或报告行为，不自动确认能力可靠性。

首屏不生成全行业能力总评、成熟度百分比或抵达日常生活的时间预测。融资及公司估值不作为技术进步的替代指标。

主导航保留“近期解读”和“资料库”；公司、资本、论文、核心覆盖、订阅、历史路线、补证入口在资料入口或页脚可达。旧地址保持有效，旧研究正文不在本轮删除。README 核心阅读区与首页共享解读身份、内容和顺序，原有生成区块保留在明确的资料折叠区，不能在日更时覆盖新结构。

## 数据边界与内容结构

新增 `src/progress-explainers/`，独立承担契约、草稿生成、核验、选取、保留与 Markdown 投影；不把整套新逻辑写进现有大型入口文件。

公开产物路径为 `site/data/progress-explainers.json`，采用 `schemaVersion: 1`。记录产物生成时间、最近成功内容更新时间、本次核查时间、运行状态和零至三篇卡片；卡片保持稳定 ID、修订版本和原始规范记录引用。

卡片引用现有规范事件或可公开研究记录，不从原始抓取候选、发现层或失效记录直接生成。每项事实必须引用当前有效的规范事实/证据 ID；来源链接由规范记录解析，不采用模型自行返回的 URL。研究作者报告只按作者报告呈现，不要求虚构公司实体。

内容字段为：`titleZh`、两句 `factsZh`、`changeZh`、`meaningZh`、`limitationsZh`、可选 `backgroundZh`、可选有证据的 `comparison`、证据情境标签、字段级证据引用、日期及规范身份。日期分别表达事件日、披露日和核查时间，未知保留未知，运行时间不得代替事件日。

AI 只接收合格的结构化事实及必要的已核验来源片段；网页文本视为不可信资料，不作为指令。草稿不是事实源，不能反向写入规范账本。

默认从最近三十天内具备明确事件日或披露日的合格记录选题。排序优先使用可验证的实质变化时间降序，同一事件或同一论文版本去重，以稳定 ID 解决并列；不因公司知名度、融资金额或来源数量直接宣称认知价值。只保留能写清具体新增信息和限制的完整解读，不以空泛“推动行业发展”占位。

无合格近期内容时可以保留仍有效的上次解读，但必须标为历史解读并显示原内容日期；不得刷新成“今日新进展”。研究与产业不设置强制配额。

## 草稿与自动发布门槛

复用已有模型客户端、凭据和超时/预算约束，不新增服务商、Secret 或改变现有运行默认值。为新步骤记录独立的请求成功、结构拒绝、证据拒绝、超时和回退状态，不输出密钥或完整原始模型响应。

发布前逐项检查：中文内容完整、字段非空且非占位、身份及证据有效、数字与实体有对应依据、对比确有基线、情境标签不升级事实、无撤回或冲突。解读与事实明确分栏；证据引用存在并不等于语义已被证明，不将引用数量当作事实正确性的保证。

对新增自然语言解释执行受现有预算约束的语义复核；复核不通过或不可用时不发布新草稿。复核结果仍是辅助审核，不在用户界面宣称机器已保证内容无误。只有全部门槛通过的新卡才进入自动发布产物，失败草稿留在内部审阅层。

一期不提供人工 CMS，不新增自动发帖、Issue 或社区推广动作。已有纠错入口继续使用。

## 状态、撤回和事务一致性

必须区分：

- 正常更新：有通过门槛的新解读。
- 无合格新变化：本轮处理完成，但没有新的合格解读。
- 更新受限：模型、来源或转换步骤失败；仅保留经当前规范事实重新核验仍有效的旧解读。
- 内容暂不可用：没有安全可用的解读，或者旧内容有效性无法确认。

产物本次处理时间与内容上次成功时间分开，前端显示的是实际状态，不把生成成功当成数据全部健康。

撤回、冲突、失效身份和被移除证据优先于保留上一版。旧解读的依赖不再有效时，剔除受影响卡并形成安全产物，必要时零卡；不得因模型失败而绕过剔除。被影响的标题、事实、解释及对比都需重新生成或退出，不能仅更换来源链接。

将解读 JSON、README 投影和页面消费数据接入现有暂存及整组验证。首页不再次排序、不独立调用 AI，也不从旧 dashboard 候选区兜底补卡。前端加载失败显示明确错误，不伪造日期或使用硬编码新闻。

校验失败不交换不一致产物。已发现撤回但安全产物发布失败时，运行必须标为失败并暴露阻断步骤，不能声称撤回已经同步到线上。发布后的同版验证是独立验收。

## 代码影响范围

- 新模块：`src/progress-explainers/`，负责数据与内容契约、核验、投影及保留规则。
- 接入：`src/main.ts`、现有暂存发布与 `src/validate-release.ts`，最小连接新产物，不改其他产品的契约版本。
- 展示：`site/index.html`、`site/app.js` 的首页入口及新解读展示模块、`site/styles.css`、`README.md`、`README.en.md`、`assets/social-preview.svg`。
- 政策：在 `FACTS_POLICY.md` 增加新首页解读规则，原有旧产品规则明确适用范围，不静默改写旧账本语义。
- 校验：对应单元、渲染、真实生成、暂存发布、发布契约测试。

本轮不重写抓取器、扩源、迁移框架、删除档案、改工作流权限/计划、引入账户/追踪、建立全行业地图或新增 Feed。

## 验收

技术验收覆盖：合格事件与论文、零内容、重复记录、日期未知、英文/空泛/占位草稿、虚构数字或对比、发现层证据、作者报告与独立复现区分、模型失败、冲突及撤回后旧卡剔除、旧卡仍有效时的回退、产物不一致时拒绝交换。

完整生成测试必须使用隔离输出目录，连续两次验证不重复制造卡片，且 README 与首页消费产物的身份、顺序和内容一致。执行类型检查、全量测试和发布校验；桌面与 390px 手机布局检查正文、折叠区、证据链接、无横向溢出及错误状态。

产品验收需要真实读者，不由自动测试或 agent 模拟替代：非专业读者能复述至少一项具体变化及一个限制，不把演示误认成广泛部署。此项未开展时明确标为待验证。

本次“开始重构”授权本地开发与验证；不沿用上一轮视觉任务的发布授权。本地完成后报告分支和测试结果，合并推送及真实线上生成须按当前任务获得明确授权。
