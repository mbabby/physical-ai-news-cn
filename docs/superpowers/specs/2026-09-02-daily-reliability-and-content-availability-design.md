# 日报按时性与内容可用性设计

## 背景与目标

9 月 2 日北京时间 08:00、08:30、09:15 的日报定时事件均未被 GitHub Actions 投递，但既有健康看门狗仍把 9 月 1 日的产物判为可用。与此同时，LLM 能把只有中文标题、但缺失或占位摘要的响应计为成功；行业脉搏又绕过了受控批处理。这造成“运行成功或部分成功、首页产业信号却为空”的误导。

本专项在不降低公开事实门槛的前提下，使日报在北京时间当天按时恢复、让健康状态如实反映当天新鲜度，并让局部 LLM 故障不扩大为整类内容空窗。

## 范围与非目标

本期包含：

- 以 `Asia/Shanghai` 日历日和 09:20 SLA 判定日报新鲜度；
- 独立健康看门狗在 09:25 对缺失日报仅派发一次安全恢复任务；
- 日报恢复模式的幂等跳过、并发防护与可追溯状态；
- LLM 完整中文事实简介校验、受控并发、区分提供方故障和无效输出、已验证缓存优先；
- 仅针对高可信中文一手行业事实的确定性原文回退；
- Dashboard 与首页披露最新日期、当天状态、公开条目、候选积压和安全降级原因；
- 候选实体质量指标和非法实体输入的隔离，防止继续污染候选层。

本期不包含：把候选直接升为公开事件、自动翻译英文一手来源、伪造公司名、删除既有历史实体，或保证 GitHub 自身 cron 绝不丢投递。若 GitHub 的日报与恢复看门狗均未被投递，需要外部调度器作为下一期 SLA 防线。

## 架构

### 当日新鲜度与恢复

`runtime/health` 保持历史成功率和公开内容质量，但新增独立的日报新鲜度评估。它输出北京时间预期日期、截止前的 `pending`、当日已生成的 `current`、截止后缺失的 `missing`。`missing` 会使健康验证失败；历史 36 小时陈旧规则仍作为灾难级保护。

健康看门狗保留每三小时的只读检测，并新增北京时间 09:25 的恢复时隙。恢复时隙只在新鲜度为 `missing` 时，通过最小 `actions: write` 权限派发 Daily workflow 的 `recovery=true`；它不生成内容、不写仓库。Daily workflow 在启动后重新读取当天 receipt 和日报文件，已经生成时安全 no-op。并发组继续保证同一时刻只有一个写入者。

### LLM 与公开事实门槛

模型响应只有同时包含完整中文标题和非占位中文事实简介时才计为成功。研究摘要另需满足现有两句事实简介门槛。无摘要、模型输出格式错误属于单条无效输出，不代表提供方故障；仅 HTTP/网络/认证等提供方故障计入熔断。行业、研究和脉搏使用受限批次，避免 `Promise.all` 在熔断前放大请求。

顺序为：已验证历史中文副本 → 合格 LLM 结果 → 高可信中文官方行业原文的确定性回退 → 候选层。最后一项严格要求官方公司/实验室、一手等级、非研究、原始标题和事实摘要均为完整中文；英文来源绝不被模板化翻译或公开。

### 公开状态与候选卫生

Dashboard 接收一个不含候选标题、URL、原始错误或私密诊断的健康投影。首页展示“数据截至”“今日日报状态”“公开产业/研究条目”“候选积压”和受控降级原因。空列表呈现明确的证据门槛状态，而不是持续加载。

候选实体写入前通过轻量可接受性校验，拒绝日期、金额、赛道词、媒体标题和泛称；拒绝计数进入健康投影，但原始候选仍只在内部审阅层保留。

## 错误处理与安全边界

- 恢复派发失败使健康 workflow 明确失败，且不修改日报文件；
- 恢复派发只在恢复时隙且当天缺日报时发生，重复派发由 Daily 幂等检查和并发组消解；
- LLM 提供方错误不记录密钥、URL 参数、请求正文或文章原文；
- 无效/英文/占位文本永不绕过 `hasCompleteChineseCopy`；
- 公开 Dashboard 只输出聚合计数、枚举状态和安全原因。

## 验收标准

1. 北京时间 09:20 后无当天日报时，健康结果是 `stale`/`missing`，而非仅 `degraded`；09:20 前为 `pending`。
2. 09:25 恢复看门狗会在缺日报时派发一次 `recovery=true`，已生成或在运行时不重复产生写入。
3. LLM 只有输出完整中文事实简介时计为成功；两次提供方失败后同类请求停止，但另一类和缓存不受影响。
4. 英文或无证据内容仍停留候选层；符合约束的中文官方事实可在 LLM 故障时安全公开。
5. 首页公开显示当前日期、新鲜度和降级信息；公开 JSON 不泄露候选内容或私有诊断。
6. 全量类型检查与测试通过；真实日报连续运行两次成功，Pages 日期与日报 receipt 一致。
